# 技能: save-project

## 使用方式
用户输入 `/save-project` 或 `/save-project 关于XX项目`。

## 功能描述
深度分析当前对话，提取项目决策、架构选择、里程碑，路由到 `04_Projects/` 对应项目子目录。

## 目录结构

```
{{VAULT_PATH}}/04_Projects/
├── <项目A>/           — 英文短横线命名
├── <项目B>/
└── ...
```

每个项目一个子目录，目录内按日期累积决策文档，而不是每件事新建一个目录。

## 执行流程

### 步骤 1：分析对话
- 提取候选内容：架构决策、方案定稿、里程碑达成、评审结论、需求收敛。
- 忽略：日常执行细节、已在日报记录的内容。

### 步骤 2：项目路由
- 从对话上下文推断项目名。
- 先查 `04_Projects/` 现有子目录，命中则复用；未命中则新建（英文短横线命名）。
- 同名项目有歧义时 → 询问用户，不要猜。

### 步骤 3：写入项目文档
- 新文件：`YYYY-MM-DD-<主题>.md`；若同一主题已有文件则**追加章节**而非新建。
- 格式：
```markdown
---
title: "<文档/决策标题>"
created: YYYY-MM-DD
tags:
  - type/知识捕获
  - project/<项目名>
---

# <标题>

## 背景

## 决策 / 里程碑

- 决策1：原因和影响

## 状态

- [ ] 待办1
```

### 步骤 4：交互确认
| 时机 | 询问 |
|------|------|
| 路由前 | 项目归属有歧义时问用户 |
| 写入前 | 预览目标文件 + 追加/新建方式 |
| 写入后 | 一句话确认归档位置 |

## 注意
- 同主题复用已有文件，避免目录里同一项目多份碎片文档。
- 项目 tag 用 `project/<项目名>`，保持与日报/周报一致可检索。
- 与 `/save-to-brain` 关系：`save-to-brain` 全量归档；`save-project` 专管项目决策单类。

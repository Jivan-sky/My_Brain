# 技能: save-knowledge

## 使用方式
用户输入 `/save-knowledge` 或 `/save-knowledge 关于XX的发现`。

## 功能描述
深度分析当前对话，提取非显而易见的技术知识、解决方案、踩坑记录，按主题分类写入 `03_Knowledge/` 对应子目录。

## 目录结构

```
{{VAULT_PATH}}/03_Knowledge/
├── <NN-主题>/         — 每个主题一个编号前缀子目录
│   └── YYYY-MM-DD-<描述>.md
└── _MOC.md            — 主题索引
```

主题目录**随 vault 演进，不是固定的**。写入前先 `ls` 看现有目录，以现状为准；
除非确实归属不了任何已有主题，否则不要新建主题目录。

## 执行流程

### 步骤 1：分析对话
- 提取候选知识点：新掌握的技巧、解决的 bug、非显而易见的配置、踩坑结论。
- 忽略：简单代码修改、已记录过内容、纯聊天。

### 步骤 2：分类决策
按内容主题选目录：

1. 先读 `03_Knowledge/_MOC.md`（或 `ls` 子目录），拿到当前主题清单。
2. 按内容特征匹配最接近的主题目录。
3. 匹配不到 → 询问用户，或在最接近的主题下并入既有文件。

- 主题目录由 vault 现状决定，**不要凭 skill 里没写的目录名凭空创建**。
- 带项目名的具体业务复盘，优先放 `04_Projects/<项目>/` 而不是 `03_Knowledge/`——知识层只放可复用的主题知识。

### 步骤 3：写入知识文件
文件名：`YYYY-MM-DD-<描述性名称>.md`（英文短横线命名，如 `2026-07-30-platform-probe.md`）。

格式：
```markdown
---
title: "<知识点标题>"
created: YYYY-MM-DD
tags:
  - type/knowledge
  - <分类tag，如 ai/claude / 工具链 / 业务域/<项目>>
source: "[[<源笔记>]]"
---

# <知识点标题>

> 一句话核心结论。

## 背景

发生了什么、为什么记录。

## 结论 / 解决方案

- 关键点1
- 关键点2

## 验证 / 效果

如何验证、实际效果。
```

- frontmatter 必须含 `title`、`created`、`tags`、`source`。tags 中的 `type/knowledge` 是分类词表的固定取值，一篇有且仅有一个 `type/`。
- `source` 必须回链派生这条知识的 L1 记录（日报/项目笔记），例如 `source: "[[2026-07-15]]"`。知识卡是「指针 + 摘要」——**提炼不等于搬移**，源记录留在原地。

### 步骤 4：交互确认
| 时机 | 询问 |
|------|------|
| 分类前 | 若分类有歧义，问用户落哪个目录 |
| 写入前 | 预览文件名 + 目录，确认 |
| 写入后 | 一句话确认归档位置 |

## 注意
- 同一知识点重复出现时跳过（写前检查目标目录是否有类似文件）。
- 与 `/save-to-brain` 关系：`save-to-brain` 是全量归档（知识+决策+待办）；`save-knowledge` 专管知识单类。

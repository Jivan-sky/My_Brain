# 技能: save-knowledge

## 使用方式
用户输入 `/save-knowledge` 或 `/save-knowledge 关于XX的发现`。

## 功能描述
深度分析当前对话，提取非显而易见的技术知识、解决方案、踩坑记录，按主题分类写入 `03_Knowledge/` 对应子目录。

## 目录结构

```
{{VAULT_PATH}}/03_Knowledge/
├── 01-AI与Claude/     — Claude Code、AI Agent、模型、提示词
├── 02-工具链/         — API 对接、CLI 工具、平台探针
├── 03-业务域/         — 按项目分子目录（每个项目一个，自带 README）
└── 04-开发与运维/     — 代码技术、服务器运维、环境排障
```

## 执行流程

### 步骤 1：分析对话
- 提取候选知识点：新掌握的技巧、解决的 bug、非显而易见的配置、踩坑结论。
- 忽略：简单代码修改、已记录过内容、纯聊天。

### 步骤 2：分类决策
按内容主题选目录：

| 内容特征 | 落目录 |
|---|---|
| Claude Code / AI 模型 / Agent / prompt | `01-AI与Claude/` |
| 第三方 API / CLI 工具 / 脚本工具 / 平台对接 | `02-工具链/` |
| 某个业务域的领域知识、规则、SOP | `03-业务域/<项目>/` |
| 语言/框架技术、服务器、环境排障 | `04-开发与运维/` |

- `03-业务域` 下的项目子目录名由上下文推断，不存在则创建。
- 无法确定项目归属的业务知识，放 `03-业务域/` 根或并入最接近的项目。

### 步骤 3：写入知识文件
文件名：`YYYY-MM-DD-<描述性名称>.md`（英文短横线命名，如 `2026-07-30-platform-probe.md`）。

格式：
```markdown
---
title: "<知识点标题>"
created: YYYY-MM-DD
tags:
  - type/知识捕获
  - <分类tag，如 ai/claude / 工具链 / 业务域/<项目>>
---

# <知识点标题>

> 一句话核心结论。

## 背景

发生了什么、为什么记录。

## 结论 / 解决方案

- 关键点1
- 关键点2

## 验证 / 效果

如何验证、实际效果。
```

- frontmatter 必须含 `title`、`created`、`tags`，tags 至少含 `type/知识捕获`。

### 步骤 4：交互确认
| 时机 | 询问 |
|------|------|
| 分类前 | 若分类有歧义，问用户落哪个目录 |
| 写入前 | 预览文件名 + 目录，确认 |
| 写入后 | 一句话确认归档位置 |

## 注意
- 同一知识点重复出现时跳过（写前检查目标目录是否有类似文件）。
- 与 `/save-to-brain` 关系：`save-to-brain` 是全量归档（知识+决策+待办）；`save-knowledge` 专管知识单类。

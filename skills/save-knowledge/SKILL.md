# 技能: save-knowledge

## 使用方式
用户输入 `/save-knowledge` 或 `/save-knowledge 关于XX的发现`。

## 功能描述
深度分析当前对话，提取非显而易见的技术知识、解决方案、踩坑记录，按主题分类写入 `03_Knowledge/` 对应子目录。

## 目录结构

```
{{VAULT_PATH}}/03_Knowledge/
├── 01-踩坑_漏点/       — bug、报错、静默失败、踩坑结论
├── 02-部署_运维/       — docker/镜像、cron、k8s、环境与运行时排障
├── 03-接口_数据/       — 第三方 API、平台探针、字段口径、数据结构
├── 04-技术栈_归纳/     — Claude Code、Agent、prompt、框架与协议原理
└── _MOC.md            — 主题索引
```

上面是**本库约定**的固定 4 桶，不新增。**但以 vault 现状为准**：首次运行先 `ls` 确认，
你的 vault 若用别的切法，改这张表——不要新建 skill 里没写的目录。

## 执行流程

### 步骤 1：分析对话
- 提取候选知识点：新掌握的技巧、解决的 bug、非显而易见的配置、踩坑结论。
- 忽略：简单代码修改、已记录过内容、纯聊天。

### 步骤 2：分类决策
按内容主题选目录：

| 内容特征 | 落目录 |
|---|---|
| bug / 报错 / 静默失败 / 踩坑结论 / 排查路径 | `01-踩坑_漏点/` |
| docker / 镜像 / 容器网络 / cron / k8s / 部署环境 | `02-部署_运维/` |
| 第三方 API / 平台探针 / 字段口径 / 数据结构 | `03-接口_数据/` |
| Claude Code / Agent / prompt / 框架与协议原理 | `04-技术栈_归纳/` |

- 选之前先读 `03_Knowledge/_MOC.md`（或 `ls` 子目录）确认现状，**不要凭 skill 里没写的目录名凭空创建**。
- 按**知识本身的性质**分类，不按项目分。带项目名的具体业务复盘，优先放 `04_Projects/<项目>/` 而不是 `03_Knowledge/`——知识层只放可复用的主题知识。
- 实在归不进已有主题 → 询问用户，不要新建主题目录。

### 步骤 3：写入知识文件
文件名：`YYYY-MM-DD-<描述性名称>.md`（英文短横线命名，如 `2026-07-30-platform-probe.md`）。

格式：
```markdown
---
title: "<知识点标题>"
created: YYYY-MM-DD
tags:
  - type/knowledge
  - <主题tag，从 {{VAULT_PATH}}/_词表.md 的受控词表里选，可多个>
source: "[[<源笔记>]]"
---

# <知识点标题>

> 一句话核心结论。

## 背景

发生了什么、为什么记录。

## 结论 / 解决方案

- 关键点1
- 关键点2

## 验证 / 效果

如何验证、实际效果。
```

- frontmatter 必须含 `title`、`created`、`tags`、`source`。
- `tags` 里**恰好 1 个** `type/`，值为 `type/knowledge`（旧写法 `type/知识捕获` 已废弃）。其余 tag 只能从 `_词表.md` 受控词表里选；要加新 tag，先加进词表再用。
- `source` 必须回链派生这条知识的 L1 记录（日报/项目笔记），例如 `source: "[[2026-07-15]]"`。知识卡是「指针 + 摘要」——**提炼不等于搬移**，源记录留在原地。
- 写完把新卡片登记进 `03_Knowledge/_MOC.md`。

### 步骤 4：交互确认
| 时机 | 询问 |
|------|------|
| 分类前 | 若分类有歧义，问用户落哪个目录 |
| 写入前 | 预览文件名 + 目录，确认 |
| 写入后 | 一句话确认归档位置 |

## 注意
- 同一知识点重复出现时跳过（写前检查目标目录是否有类似文件）。
- 与 `/save-to-brain` 关系：`save-to-brain` 是全量归档（知识+决策+待办）；`save-knowledge` 专管知识单类。

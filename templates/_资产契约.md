# 📜 资产契约

> 本页定死**哪些不可删**。任何整理动作前先读本页。

## 一句话

**日报/周报/月报/项目笔记 = 里程记录，永久保留，不可删、不可移出、不可合并。**
Knowledge 是从它们派生的视图，丢了能重建；里程记录丢了重建不了。

## 四级资产

| 级别 | 目录 | 性质 | 保留 | 可否移动 |
|------|------|------|------|----------|
| **L1 里程记录** | `01_Daily/` | 事实表（append-only 事件日志） | **永久** | ❌ 不可移出目录、不可合并、不可删 |
| **L1 里程碑** | `02_Reports/周报\|月报/` | 定期快照 | **永久** | ❌ 同上 |
| **L1 业务实体** | `04_Projects/` | 主表（项目全景/迭代/待办/凭据） | **永久** | ❌ 只可在项目子目录内归位 |
| **L2 派生视图** | `03_Knowledge/` | 从 L1 提炼的意象 | 可重构 | ✅ 可重组、可重切目录 |

## 派生规则（关键）

1. **提炼 ≠ 搬移。** 从日报抽知识点，**原日报留在原地**，知识点新建卡片。
2. **Knowledge 卡是「指针 + 摘要」**，必须回链源记录：frontmatter `source: "[[YYYY-MM-DD]]"`。
3. **删 Knowledge 卡不损失信息**（源还在）；删 L1 记录 = 永久损失。

## L2 结构：4 桶 + 原子卡

**按问题域分桶，不按载体分。** 你召回知识时想的是「我遇到 X 问题」，不是「这是工具还是框架」。

| 桶 | 收纳判据 |
|----|---------|
| `01-踩坑_漏点/` | 出 bug，定位到**反直觉**的原因 |
| `02-部署_运维/` | 让东西**在机器上跑起来**（容器/镜像/定时/环境） |
| `03-接口_数据/` | 跟**外部系统**对接：探接口、要权限、取数、格式 |
| `04-技术栈_归纳/` | 模型 / Agent / prompt / **上下文** / 技术栈与协议的系统学习包（handbook） |

> 桶名以磁盘为准。你要用别的切法就改这张表 —— 但要**一处改、处处改**：`_词表.md` 的主题 tag、各 skill 里的路由表，指着的是同一批目录名。

**拆分判据**：某桶 ≥12 篇，**或**桶内出现 ≥5 篇同一子主题 → 才升二级目录。

**原子卡**：一张卡只回答一个「是不是」问题，一句话说完。frontmatter 带 `atom` 标签，**平铺在所属桶内** —— 不建 `_atoms/` 子目录。必须写 `source` 回链父笔记。

## 禁止的动作

- ❌ 删除、移出、合并、打包封存 L1 记录。
- ❌ 在整理/精简/重构方案里提议「删掉已提炼的日记」——**删事实表留视图是本末倒置**。

## 允许的动作

- ✅ L1 内部归位（错位文件移回同类目录）
- ✅ 补 frontmatter 标签
- ✅ 建索引 / MOC 指向 L1
- ✅ 从 L1 派生知识卡

## 批量操作前置条件

任何涉及 L1 的批量改动，必须：

1. 先做 tar 备份
2. dry-run 打印全量 diff
3. 人工确认后再执行
4. 脚本读写必须带 `newline=''`（否则 Python 会把 LF 静默转成 CRLF）

## 完整性核查（每次大批量操作后跑）

三条不变量。任一条破了，就说明有笔记游离在体系之外：

1. **每篇恰好 1 个 `type/`** —— 数量不是 1，说明 frontmatter 漏写或写重。
2. **`sum(type 计数) == md 文件总数`** —— 对不上，说明有笔记没有 frontmatter。这种笔记在 Dataview / Bases 视图里等于不存在。
3. **L1 记录数只增不减** —— 安装时由 `install.sh` 把当时的值写进脚本，日后低于它即报错。

```bash
cd "<VAULT_PATH>"
python _scripts/vault_doctor.py     # 8 项体检；exit 1 = 有违规
python _scripts/check_links.py      # 只看 wikilink 有效性
```

`vault_doctor.py` 加 `--md` 会把报告写到 `_scripts/_doctor_report.md`。

只读，不改任何笔记。**它不是门禁** —— 跑不跑、什么时候跑，由你定。
